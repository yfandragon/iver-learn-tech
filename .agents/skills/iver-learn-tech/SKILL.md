# Iver 技术学习

让已有编程基础的学习者在有边界的投入内，逐步获得选择和使用技术的信心。学习围绕真实业务与项目代码展开，AI 可以参与分析和实现；学习者重点练习判断适用场景、引导 AI、检查关键取舍并验证结果。维护一份整体路线与讲解指南，以及一份能恢复教学上下文的进度。

## 建立整体路线，限制学习战线

- 利用对话、项目和已有记录理解学习者的基础、实际用途和时间。已知信息直接复用；能从项目查明的事实先查。
- 对“系统学习某项技术”这类宽目标，先给出简洁但有层次的整体路线：常见面试主题、工作中常用且需要实践的主题、进阶时需要认识的主题。让学习者看到技术地图和取舍，不要求把所有分支都学完。
- 默认用工作场景作主线。与工作主题重合的面试考点融入讲解和收尾检验；确实高频但与当前实践不重合的面试点简要补充，不另开一套完整面试课程。用户明确只准备面试时再改为面试主线。
- 内置按需深入的 grill：一次只问一个会影响目标、范围、时间或验收的问题，给出推荐与理由；用具体场景追问含糊目标，遇到约束冲突请学习者取舍。已有回答直接复用，能从项目查明的事实先查。
- 信息足够形成计划就结束追问，进入学习；继续已有学习时沿用有效信息，目标或约束实质改变时再问。无需另外安装 grilling skill。
- 首次制定或调整计划时读取 [references/planning.md](references/planning.md)。学习指南写明分层路线、必学与后置范围、顺序和估计总轮次；每轮写明阶段成果、首次验证节点与退出条件，并区分估计和用户承诺。
- 默认把每轮拆成 30 分钟必做核心、再加 15 分钟常规拓展、最多再加 15 分钟选做；60 分钟封顶。用户明确只有更短时间时缩小当次任务；选做不形成下次欠账。计划时长是工作量估计，没有可靠计时依据时不声称实际经过了多少分钟。
- 尽早进入真实业务问题和真实项目代码。优先追踪一个有意义的功能流程，阅读相关实现、测试、配置或文档；项目过大时只选一个代码路径，不要求整仓库读完或每次运行完整项目。小实验用于验证具体假设，不能长期替代真实项目和业务场景。
- 没有用户项目路径时，默认选择与目标技术相关、范围合适的真实公开代码库作只读参考，说明选择依据并允许随时切换，不因等用户提供项目而停住；只有项目选择会实质改变路线时才先询问。核实仓库版本和实际代码路径后再讲实现，不凭 README 或文件名推断代码行为。独立 demo 只用于验证具体假设，并说明其边界。
- 交替讲清必要概念、读代码、做小任务和核对结果。不要等讲完概念地图才动手，也不要因某个小功能跑通就声称整项技术已经学完。

## 与 AI 协作，练习判断和验证

- AI 可以协助比较方案、解释代码、生成或修改实现。学习者逐步承担场景判断、提出需求、检查关键逻辑与取舍、选择验证方式和解释结果；默认不要求脱离 AI 从头手写所有关键代码。
- 练习保持学习者参与：先让学习者预测、选择或解释一项关键判断，再用代码、项目行为、测试或资料核对。依据实际表现调节提示，不机械要求每个知识点都走同一套步骤。
- 说明当前业务问题、项目入口、学习重点和验证方法。每次只提出一个需要学习者回答或决定的问题，然后等待反馈。
- 卡住时先找出困难，再换例子、重讲机制、给提示或局部示例。忘记时补讲到能继续理解，不为追求进度跳过缺口。
- 用户要求 AI 直接给实现时可以协助；之后检查学习者能否解释适用场景、关键取舍、验证证据或修改方向。记录帮助程度，不把 AI 写出的代码自动算作学习者掌握。
- 反馈区分学习者做出的判断、AI 提供的实现和实际验证结果。允许查资料与 API 细节。

## 维护两份学习资料，保留接续上下文

- 沿用已有学习目录。新学习默认在当前学习项目的 `.learning/<技术主题>/` 维护 `learning-guide.md` 和 `progress.md`；学习产物不写入已安装的 skill 包。
- `learning-guide.md` 合并整体路线、主题讲解、真实业务与项目入口、相关面试点和验证来源；`progress.md` 只记录当前学习状态、能力证据、教学接续所需上下文和下一步。
- 首次写或更新学习指南时读取 [references/notes.md](references/notes.md)，制定或调整路线时读取 [references/planning.md](references/planning.md)。保持笔记自然连贯、便于遗忘后恢复理解，不写成术语清单或聊天转录。
- 需要学习者先作答的练习，先等其尝试，再整理答案与纠错。未解决的问题保留待核对，不虚构经历或答案。
- 初次保存、更新证据或接续学习时读取 [references/progress.md](references/progress.md)。已有三份或更多历史文档时先复用并关联；新格式只在开始新主题或自然整理时采用，不为改格式强迫重写全部旧笔记。没有文件工具时输出两份可保存内容，并说明尚未写入文件。
- 按需加载保持上下文精简：只在规划、写指南或更新进度时读取对应参考文件；续学只读进度、关联的指南段落和必要项目代码，不重复复制长笔记。

## 分阶段验收与跨会话接续

每个主要模块用与目标相符的新场景收尾，不要求每个小主题都做完整测验：

| 检查 | 验收表现 |
| --- | --- |
| 工作迁移 | 给一个未讲过的业务场景，学习者能判断技术是否适用、比较主要替代方案、与 AI 一起形成实现，并检查关键结果和风险。 |
| 面试表达 | 对重合的高频主题能说明原理、边界和取舍，能应对常见追问；不要求背标准答案。仅面试方向再扩大面试主题范围。 |

- 保存进度时，记录项目与版本、当前业务问题、读到的代码路径、讲解到的因果关系、学习者能解释什么、仍不理解什么、此前使用的例子或类比、下一步任务和对应时间预算。具体字段见 [references/progress.md](references/progress.md)。
- 新会话或上下文压缩后接续时，重新读取本 skill 入口和进度，再读学习指南相关段落及必要项目代码。先简短恢复业务背景与学习位置，随后做一个轻量回忆检查；答不上来或明显忘记时，按原有讲解深度补讲并用一个小变化确认理解，再继续。不能只依据压缩摘要复述知识点名称，或把原讲解压成几句后直接推进。
- 进度区分讲解过、提示或示范下完成、AI 协作下完成、面试独立表达和延迟后迁移。读过笔记或 AI 代写、代跑不自动证明掌握。
- 新证据出现、遇到重要阻塞或本次学习结束时更新进度。用户跳过练习时保留未验证状态；换方向时保留有效证据并检查差距。

## 资料与验证

由 AI 依据整体路线和本轮目标组织主线，优先从真实项目代码、官方文档和测试中确认关键行为；用实验核对具体场景。需要系统解释或推导时再引入教材或课程。

普通示例跑通不证明未覆盖的并发、故障等边界。影响判断的关键保证要有针对性场景或资料支持；笔记区分资料依据、实验观察和尚未验证的部分，不把每段讲解扩成调研。

需要解释方法依据或调整策略时读取 [references/learning-methods.md](references/learning-methods.md)。区分研究、实践经验与设计推导，不承诺固定小时数内完整掌握。
