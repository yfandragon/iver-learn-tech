# 学习指南的讲解写法

新主题的路线和笔记合并在 `learning-guide.md`。本指南同时帮助学习者理解技术全景和在遗忘后恢复具体判断；能力状态与下次任务只放在 `progress.md`，避免复制相同内容。

## 组织与检索

- 保留简短目录和关键判断速览，再按主题或真实问题分节。标题应能让学习者快速找到问题，例如“缓存更新后为什么还会读到旧值？”。
- 先加载或复习当前相关主题，不要每次把整份指南重新讲一遍。新增主题放到对应路线层级，并链接相关项目路径、资料和实验。
- 路线呈现面试常见、工作常用和进阶认知主题；只把当前必学部分展开成完整讲解，未学主题保留简短用途和优先级，不提前写成百科内容。

## 写给人读，讲清因果

从业务问题或项目中的真实代码路径开始，解释：问题为何出现、机制如何起作用、代码如何实现、在什么条件下结论会改变。保留足以让未来的学习者重新推理的例子、边界和修正过程。

采用自然、直接的表达。避免模板化的“定义—优点—缺点”堆叠、孤立术语表、重复结论和聊天转录。不要把临时讲解压成几句口号；也不要为了显得详尽，把无关背景写成长篇教材。

工作主题可附项目版本、文件路径、相关测试或命令，以及实际验证结果；每个主题只保留能帮助定位和恢复理解的入口。面试点融入相关主题，补充常见追问和表达重点；不重复另写整份面试题集。

## 事实、经历与纠错

- 区分真实项目观察、假设例子和有来源支持的常见误解，不虚构学习者做过或说过的事。
- 将实际疑问与纠错放到对应主题；修正错误结论时简要说明原因，避免相互矛盾的答案并存。
- 保留必要的一手来源、版本信息和实验条件。说明来源确认了什么、实验观察到了什么、还有什么未验证；不要求每段都堆引用。
- 未实际运行的代码注明示例或待验证。正常路径实验不扩展为并发、故障等未覆盖条件下的保证。
- 学习者需要先预测或作答时，等待其尝试后再整理答案。练习未完成时，只记录已讲内容和开放问题。

主题段落可按需要组合：真实问题、项目入口、机制解释、示例与边界、实际疑问与修正、AI 协作和验证方式、面试追问、来源。没有必要的栏目就省略。
