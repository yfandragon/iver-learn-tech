# 进度状态与跨会话接续

学习者资料只保留两份：`learning-guide.md` 保存整体路线和连贯讲解；`progress.md` 保存当前状态、证据和下一次接续所需的最小上下文。先检查已有目录并兼容旧文档，不为改格式强迫重写全部历史内容。

## 记录可验证的能力

| 状态 | 记录依据 |
| --- | --- |
| 未验证 | 只听过讲解、读过代码或看过示例，没有实际表现证据。 |
| 提示或示范下完成 | 在局部提示、示例或现成答案帮助下完成；注明帮助程度。 |
| AI 协作下完成 | 学习者判断了场景、引导 AI、检查关键取舍并核对结果；记录 AI 帮助与验证证据。 |
| 面试独立表达 | 不依赖 AI，能解释约定的原理、边界和常见追问。 |
| 延迟后迁移 | 间隔后在新场景中重新判断、协作实现或解释；注明日期和条件。 |

证据来自学习者的判断、解释、实际操作或经核对的结果。AI 生成或运行的代码不单独证明学习者掌握。用户自述的完成情况标为自述；未直接核实的部分保留不确定性。失败的检查也要记录，保留历史证据并明确当前薄弱点。

## 接续上下文

进度文件保持精简，但必须足以让新会话恢复原来的教学深度。只记录接续所需的信息，不复制学习指南全文或完整聊天记录：

```markdown
# 技术主题：学习进度

更新日期：实际学习日期
记录格式版本：1

## 当前目标与位置

- 学习用途和目标：
- 整体路线当前位置：链接到学习指南相关主题。
- 项目与版本：仓库／分支或标签／关键目录；未核实项明确标出。
- 当前问题与代码路径：本次正在理解的流程、入口和相关测试。

## 能力证据与理解状态

| 主题 | 状态 | 学习者实际表现 | AI／提示帮助 | 证据与日期 |
| --- | --- | --- | --- | --- |

- 已能解释：用自己的理解概括关键因果。
- 仍不清楚：具体误解、遗漏或待核实问题。
- 讲解锚点：需要恢复的例子、代码路径、类比或关键推理；链接到学习指南，不抄全文。

## 下次接续

- 先恢复的问题与背景：
- 轻量回忆检查：
- 若答不上来要补讲的主题和目标深度：
- 当前待答问题、是否已作答及接续动作：
- 下一个最小任务及项目入口：
- 本轮时间预算：核心任务、选做拓展及当次更短约束；只记录可核实的实际耗时。
```

按实际情况删去空字段，但保留可用的项目路径或未获取的原因、理解缺口和讲解锚点。避免只写“继续学习”这类无法指导新会话的单行停点。

## 更新与接续流程

- 新学习开始时建立或沿用 `.learning/<技术主题>/`；只在学习者项目保存学习文档，不写入已安装的 Skill 包。
- 形成新能力证据、出现重要阻塞或结束学习时更新进度。提出需要接续的问题时，在等待作答前同步记录本轮讲解、包含必要条件和选项的完整待答题及接续动作；问题未答时不记为掌握，回答或跳过后更新状态，避免重复安排已讲内容。项目版本、路径或下一任务改变时同步修正。
- 新会话先读 `progress.md`，再只读学习指南中链接的相关主题和必要项目代码；不要为恢复上下文加载整份长指南或重复追问已有信息。
- 记录格式缺少版本或版本较旧时，按旧结构保守读取；自然更新当前主题时再最小化补齐，不批量迁移历史文件。若未来结构确实不兼容，只调整当前正在使用的进度文件并保留已有能力证据，不另建迁移文档，除非迁移本身已复杂到需要独立说明。
- 先用几句话恢复当前问题和学习位置。当前消息已作答时先核对回答并更新状态，按理解情况补讲或继续；尚未作答但表示忘记或答不上来时，依据学习指南和代码按原有深度补讲，补足例子和因果后再用小变化检查。其他情况下，有待答题先恢复并等待，否则做轻量回忆检查。不能因读过笔记、答错一次或时间紧就压成一句结论并跳到新内容。
- 通过后从进度中的最小任务继续。没有已学内容时直接开始当前任务。
