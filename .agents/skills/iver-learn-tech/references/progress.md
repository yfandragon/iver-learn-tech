# 学习目录与进度记录

## 目录与文件职责

优先沿用已有学习目录和文档。没有时，在当前学习项目下使用 `.learning/<技术主题>/`，主题名保持稳定；位置不明确且会影响写入时才询问。

| 文件 | 职责 |
| --- | --- |
| `plan.md` | 本轮方向、知识地图、范围、顺序、预计投入与验收。格式见 [planning.md](planning.md)。 |
| `notes.md` | 面向人阅读的解释、实例、疑问与纠错。写法见 [notes.md](notes.md)。 |
| `progress.md` | 真实能力证据、当前停点、下一任务和保持检查。 |

信息足够开始时建立简短计划和进度；随实际讲解和练习增量生成笔记。已有知识地图或笔记直接关联，不同时维护两份相同内容，也不为采用新格式强制改写全部旧记录。

学习产物属于学习项目，不写进已安装的 skill 包。先看项目现状，再选择作品或实验入口。记录相对路径，必要时补充项目位置和启动说明。没有文件工具时输出可供保存的文档，并明确尚未写入文件。

## 能力状态与证据

| 状态 | 记录依据 |
| --- | --- |
| 未验证 | 尚未练习，或只是讲解、阅读过，没有独立表现证据。 |
| 提示下完成 | 学习者在示例、提示或现成答案的帮助下完成，注明帮助程度。 |
| 独立完成 | 学习者通过本轮约定的对应验收，注明方向、任务和允许查阅的资料；应用看关键逻辑与变更，面试看解释、边界和追问。 |
| 延迟后通过 | 在后续学习中通过相关回忆或应用挑战，注明日期、条件与帮助程度。 |

证据来自学习者的答案、代码、预测及核对结果，或实际操作反馈。用户自述完成时标明自述，未直接核验的部分保留不确定性。AI 代写代码和代跑示例只能证明相应行为，不能单独证明学习者已掌握。

记录方向与验收条件，切换目标时保留已验证能力，只补查新目标的差距。后续挑战失败时保留历史证据，增加当前薄弱点与补练任务，不抹去历史，也不忽略当前困难。

## 精简格式

这是运行时填写的格式，内容足以接着学即可。

```markdown
# 技术主题：学习进度

更新日期：实际学习日期

## 当前目标与入口

- 本轮方向与验收：链接到当前计划。
- 项目与版本：已核实的环境、作品或实验入口；未知则注明。
- 笔记入口：链接到相关主题，避免复制全文。

## 能力证据

| 能力／方向 | 当前状态 | 学习者表现、结果与帮助程度 | 检查日期 |
| --- | --- | --- | --- |

## 当前停点

- 实际进展：包含未成功的尝试与已排除的问题。
- 尚需帮助之处：具体困难、误解或待核对问题。
- 下次最小任务：可以直接开始的一小步，附必要入口与验证方式。
- 下次保持检查：相关旧知识的小挑战；保留已有检查的结果与日期。
- 计划调整：必要时链接到范围、时间或目标的调整原因。
```

## 何时更新与怎样接续

得到新能力证据、出现重要阻塞或结束本次学习时更新。没有成功完成任务时也记录真实停点，不编造进展、用时或输出。

继续时先读进度，再按需读计划和相关笔记，简短说明当前位置。已有有效信息不重复询问；先检查一个与下一任务相关的旧知识，针对薄弱点补练后继续。没有已学内容时直接从当前最小任务开始。

旧记录是历史证据，不能代替当前表现。保持检查随继续学习触发；没有要求后台调度或定时提醒。
