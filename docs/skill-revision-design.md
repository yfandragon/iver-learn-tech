# 技术学习 skill：笔记与学习计划修订方案

状态：七项补充选择及 README 要求已确认；用户结束需求澄清后，已于 2026-10-30 更新正式 skill。当前设计见 [skill-design.md](skill-design.md)，使用说明见 [README.md](../README.md)。

## 修订目标

为第一版补上面向人阅读的学习笔记，以及能控制范围和学习战线的计划。每轮先明确应用、面试或兼顾的主目标，据此确定学习重点和验收方式。

## 已确认的选择

| 项目 | 已确认的选择 |
| --- | --- |
| 本轮方向 | 根据本轮需求明确应用、面试或兼顾，达到约定目标就收束。 |
| 时间与范围 | 优先控制总投入，缩小作品和选学内容；核心仍未达标时明确说明，再调整范围或时间。 |
| 笔记阅读 | 先关键点速览，再围绕问题连贯讲解，按需附实操入口或面试追问。 |
| 面试验收 | 以小实验支撑理解，检查原理解释、适用边界和追问应对。 |
| 笔记更新 | 每完成小主题或纠正关键误解就更新，结束时简短归并。 |
| 教材与核验 | AI 组织主线，按需核对一手资料，以实验验证具体场景，教材补充理解缺口。 |
| 计划追问 | 内置按需深入的 grill 方式，一次一问、给出推荐及理由，目标、范围、时间与验收明确后进入学习。 |

## 计划怎样运行

开始学习时，利用已有上下文明确本轮主目标、已有基础、可用时间和现实用途。用途已明确时直接据此安排；缺少会影响范围的信息时再询问。

计划阶段采用本 skill 自带的 grill 式追问：一次只问一个会影响计划的关键问题，给出推荐及理由；含糊目标用具体场景澄清，时间与范围冲突时请学习者取舍。能从项目查明的事实先查，已有回答直接复用。

当目标、范围、时间和验收已足够支撑计划时，结束追问，形成简短计划并进入学习。继续已有学习时沿用有效信息；方向或约束发生实质变化时，再做必要追问。不依赖外部 grilling skill，也不要求每轮走完固定问卷。

计划需要给出：

- 可验收的本轮能力目标和阶段成果。
- 必学内容、后置内容与学习顺序。
- 预计总投入与阶段用时，以及根据已知时间安排估计的收束点；估计与用户已承诺的时间分开标明。
- 首次小实验或其他可观察结果出现的节点。
- 接近预计投入但尚未达标时的调整方式。

纯概念讲解围绕当前问题展开，知识地图保持简明，随后尽早进入小任务。必要前置知识只补到能理解和验证当前问题的程度；新发现的扩展主题先放入后置清单，不自动加入本轮必学。

接近预计投入或某阶段明显超时时，先说明停点和原因，优先缩小作品或移出选学内容。达成主目标必需的核心没有掌握时，如实记录未达标，再明确调整范围或时间，不默默延长整个课程。

不为所有技术规定相同天数、概念数量或课时比例。具体计划依据本轮目标、基础和可用时间制定。

## 学习笔记怎样写

笔记面向未来可能已经遗忘的学习者。开头用简短速览恢复关键判断，正文围绕问题、场景与因果关系讲解，保留足以重新理解的例子和边界。

根据主题需要，讲清：为什么有这个问题、机制如何起作用、例子中发生了什么、实际疑问怎样解决、什么条件下需要换一种判断。按本轮目标附上必要的实验入口、操作要点或面试追问；不要求每个主题机械填满相同栏目。

表达用连贯自然的解释。实际发生的困惑与纠错融入相关主题，不保留大量重复聊天，不虚构学习者曾经提出的问题或曾经犯过的错误。假设场景、常见误解与真实经历分别标明。

每完成一个小主题或纠正关键误解，增量更新对应内容；结束时归并重复解释，更新速览与导航。尚未解决的问题保留为待核对，不编造答案。新发现的无关主题留在后续路线中，避免写笔记反过来扩大学习范围。

需要学习者先预测或回答的练习，先等其尝试，再将结果和解释整理到笔记中。读过笔记不直接算作重新掌握，恢复后仍可用一个小任务或追问检查能否应用。

## 各方向怎样验收

| 本轮主目标 | 阶段成果与验收 |
| --- | --- |
| 应用 | 可用小功能；允许查文档，自己完成关键逻辑、解释原理，并处理小变更或故障。 |
| 面试 | 用相关小实验支撑理解；独立解释原理，判断适用边界，说明选择依据并应对追问。完整功能不是每轮的统一前置要求。 |
| 兼顾 | 开始时选定两方面本轮必需的成果和验收，不默认叠加所有应用内容与面试题。 |

知识地图与笔记持续积累，方向影响本轮重点和收束条件。调整方向时更新剩余计划，保留已有有效证据。

## 教材、资料与实操怎样配合

由 AI 根据本轮目标组织教学主线，教材或课程按需提供系统解释与推导。官方文档等一手资料用于核对关键接口语义、版本与保证；实验检验明确假设在给定环境下的行为。

普通示例跑通不自动证明并发、故障等未覆盖条件下的保证。涉及关键边界时，选一个与目标有关的针对性场景或核对对应资料。笔记区分资料说明、实验观察与尚未验证的部分，保留必要来源，不把每段讲解都扩展成独立调研。

## 文件职责

### 仓库使用说明

根目录 `README.md` 作为 GitHub 使用者的说明入口，面向人说明如何安装、开始与继续学习。随 skill 版本同步维护，沿用现有 README，不另设重复的使用手册。

说明需要覆盖：

- 用途、适用基础，以及应用、面试或兼顾三种本轮目标。
- 安装方式和一条可直接使用的快速开始示例。
- 计划阶段如何按需追问、如何控制学习范围与预计投入。
- 学习中会生成哪些文档、保存在哪里、分别用于什么。
- 如何继续已有学习、回看笔记，以及调整目标或学习节奏。
- 必要的方法依据、使用边界和详细资料入口。

`SKILL.md` 负责给 AI 提供执行规则；README 负责让使用者知道如何使用。具体安装细节在更新说明时按实际支持的运行环境核对。

### 每门技术的学习文档

沿用原有学习目录。新学习默认使用 `.learning/<技术主题>/`：

| 文件 | 职责 |
| --- | --- |
| `plan.md` | 本轮目标、知识地图、学习顺序、预计投入、阶段成果、首次验证节点与退出条件。 |
| `notes.md` | 面向人阅读的速览、问题讲解、例子、疑问与纠错，以及必要的实践或面试入口。 |
| `progress.md` | 当前停点、能力证据、实际表现、下一步任务和保持检查。 |

沿用已有记录和内容，不为采用新格式重复创建知识地图或改写全部旧笔记。记录之间以链接关联，各自内容保持简短且只维护一份；学习产物不写进已安装的 skill 包。
