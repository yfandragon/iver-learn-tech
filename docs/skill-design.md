# 技术学习 skill 当前设计

面向已有编程基础、希望把新技术用于工作并能讨论相关面试重点的人。以真实项目为学习主线，通过 AI 协作、可读学习指南和轻量验证形成可迁移的判断能力。

正式入口为 [SKILL.md](../.agents/skills/iver-learn-tech/SKILL.md)，面向使用者的说明为 [README.md](../README.md)。

## 路线、优先级与时间

先列出一项技术的主要主题，并按面试常见、工作常用、进阶认知标层级。工作场景为默认主线，重合面试内容合并讲解；少量不重合的高频面试点简要覆盖。路线用于让学习者看见全景，不意味着每个主题都要深入。

按需澄清基础、现实用途、项目入口、可用时间和验收。每轮按 30 分钟核心、约 45 分钟常规、60 分钟封顶拆分；时间是计划工作量，不在缺少可靠计时信息时声称实际耗时。整体轮数和投入按路线估算，估算依据应能从阶段数与单轮预算推导；项目、基础或范围未知时给出区间和不确定性，不伪造精确时长或期限。接近估计时缩小选学范围，不静默延期。

## 教学与 AI 协作

围绕真实业务问题阅读相关项目流程、实现和验证入口，不要求每轮运行或读完整个项目。用户没有提供项目路径时，默认挑选相关且可读的真实公开代码库作只读参考，说明选择依据并允许切换；仅在项目选择会实质改变路线时才先询问。先核实仓库版本与代码路径，不凭 README 或文件名断言实现。独立实验用于验证具体假设，不能长期替代真实项目情境。

AI 可以比较方案、生成或修改代码。学习者练习判断适用场景、说明需求、检查关键取舍、选择验证方式并解释结果，不以脱离 AI 手写所有代码作为默认验收。每个主要模块用新业务场景检查迁移，并对重合的面试主题检查表达。

## 学习文档

默认学习目录为当前项目的 `.learning/<技术主题>/`，沿用已有内容，避免同时维护多份相同知识地图。学习产物与安装的 skill 包分开。

| 文档 | 职责与更新时机 |
| --- | --- |
| `learning-guide.md` | 合并分层路线和面向学习者的连贯主题讲解，附项目入口、相关面试点和验证来源。 |
| `progress.md` | 能力证据、理解缺口、项目与业务上下文、讲解锚点和下一任务。 |

学习指南面向未来可能已经遗忘的学习者，用自然连贯的讲解恢复因果关系和关键判断。进度保留足够的教学上下文，使新会话能够恢复业务场景和原讲解深度，但不复制指南或聊天记录。新格式只用于新学习或自然整理，不强迫迁移旧资料。

Skill 的四个内部参考文件分别负责路线规划、指南写作、进度接续和学习方法依据，按当前任务按需加载；学习者仍只维护上述两份文档。入口保持共享规则精简，避免重复引用、长上下文和不必要的运行时依赖。

## 同类 skill 的工程对照

2026-11-02 查阅了 [OpenAI skill-creator](https://github.com/openai/skills/blob/main/skills/.system/skill-creator/SKILL.md)、[SugarMGP/study.skill](https://github.com/SugarMGP/study.skill/blob/main/SKILL.md) 和 [casankalppawar/teach-upgrade](https://github.com/casankalppawar/teach-upgrade/blob/main/teach/SKILL.md)。这里比较的是文件组织、上下文路由、状态保存和依赖成本，不比较教学内容优劣，也不把仓库热度当质量证据。

| 工程点 | 同类实现可借鉴之处 | 本 skill 的取舍 |
| --- | --- | --- |
| 上下文成本 | OpenAI skill-creator 建议入口保持精简、参考资料按需加载；`study.skill` 用路由表将较多流程拆到不同参考文件。 | 保留一个入口和少量按场景加载的参考文件；不引入多层路由器或大型课件资源。当前入口 61 行，skill 自身无运行时依赖。 |
| 跨会话状态 | `teach-upgrade` 把全景地图、对话日志、复习稿等拆分，并要求按需创建；`study.skill` 对状态格式和迁移提供明确约束。 | 学习者只保留指南与进度两份文件，分别作为知识和状态的单一事实来源；进度增加轻量格式版本，旧格式兼容读取、只在自然更新时最小迁移。 |
| 恢复可靠性 | 同类 skill 明确把续学、复习和状态读取做成独立流程。 | 新会话或上下文压缩后重新读取当前 skill、进度和相关指南/代码；发现遗忘按原讲解深度补讲。 |
| 工具与可移植性 | `teach-upgrade` 展示了跨 agent 安装脚本；`study.skill` 包含状态脚本和课件界面，适合更重的课程产品。 | 目前没有需要脚本保证的重复性计算或状态写入，所以不增加运行时和安装依赖；提供 Codex 的 `agents/openai.yaml`，跨 agent 表现尚未做验收。 |

值得采用的是明确的上下文恢复与轻量状态演进；大型状态机、复习调度器、viewer、额外学习产物不符合当前短时、低负担目标。若未来出现多主题批量学习、复杂复习队列或大量旧记录迁移，再重新评估是否需要脚本和更严格 schema。

## Skill 工程约束

入口文件承载适用边界、共同决策规则和流程路由；路线规划、指南写作与续学细节分别放在按需加载的参考文件中。`learning-guide.md` 是路线和讲解的单一事实来源，`progress.md` 只保存证据和接续指针，避免互相复制。保持文件结构稳定、引用相对且可验证，不增加没有明确运行收益的依赖或辅助文件。

## 验收与接续

| 本轮主目标 | 验收 |
| --- | --- |
| 工作迁移 | 对新业务场景判断适用性和替代方案；能与 AI 形成实现、检查关键结果并说明取舍。 |
| 面试表达 | 独立解释高频主题的原理、边界和权衡，回应常见追问，不要求背答案。 |

进度区分讲解过、提示或示范下完成、AI 协作下完成、面试独立表达和延迟后迁移。继续时先读进度，再只读取相关指南段落和必要项目代码；轻量检查后若发现遗忘，按原讲解深度补讲再继续。

## 资料与适用边界

AI 组织主线，一手资料和真实项目代码用于核对关键语义、版本与保证，实验验证明确场景，教材补充理解缺口。正常示例跑通不证明未覆盖的故障或并发边界，读指南本身也不证明掌握。

具体流程与模板由 skill 包内参考文件维护；本文记录整体设计。方法证据与设计推导分开，实际教学效果仍需真实使用验证。
