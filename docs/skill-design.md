# 技术学习 skill 当前设计

面向已有编程基础、希望学习新技术的人。以每轮实际用途决定应用、面试或兼顾的主目标，用有范围的学习计划、真实小任务、讲解笔记与能力证据支持持续学习。

正式入口为 [SKILL.md](../.agents/skills/iver-learn-tech/SKILL.md)，面向使用者的说明为 [README.md](../README.md)。

## 方向与学习计划

根据已有对话、项目与学习记录明确目标和约束。内置按需深入的 grill，一次一个关键问题，给出推荐及理由，澄清含糊目标与时间、范围之间的冲突。信息足够形成计划后就开始；已有信息直接复用，可查明的事实先查，不引入外部 grilling skill 依赖。

计划写明本轮能力目标、必学与后置范围、简明知识地图、学习顺序、预计总投入、阶段成果、首次验证节点和退出条件。估计与用户承诺分开，具体节奏依据已有基础和可用时间调整。

概念讲解围绕当前问题展开，尽早进入可观察的小实验。优先从真实小需求选择任务；复杂项目可先提取独立实验。接近预计投入时优先缩小作品和选学内容，核心未达标时明确说明，再调整范围或时间。

## 学习者与 AI 的分工

AI 可以准备环境、脚手架和外围代码，学习者逐步接手当前要学的关键逻辑、实验、配置和判断。支持程度从示例、提示逐渐减少，依据实际表现调整。

提出当前需要学习者完成的步骤后等待反馈，卡住时先定位困难、给提示，再缩小步骤或给局部示例。完整示例可以按要求提供，能力只按学习者实际表现记录。

## 学习文档

默认学习目录为当前项目的 `.learning/<技术主题>/`，沿用已有内容，避免同时维护多份相同知识地图。学习产物与安装的 skill 包分开。

| 文档 | 职责与更新时机 |
| --- | --- |
| `plan.md` | 目标、地图、范围、顺序、预计投入与验收；开始或重要取舍改变时更新。 |
| `notes.md` | 先速览、后问题讲解，保留例子、疑问与纠错；每完成小主题或纠正关键误解时更新，结束时简短归并。 |
| `progress.md` | 能力证据、停点、下一任务与保持检查；出现新证据、重要阻塞或结束学习时更新。 |

笔记面向未来可能已经遗忘的学习者，用自然连贯的讲解恢复因果关系与关键判断，按需附实操入口或面试追问。不虚构经历，不把未解决的问题写成答案。需要学习者先作答的练习，在尝试后再整理答案与纠错。

## 验收与接续

| 本轮主目标 | 验收 |
| --- | --- |
| 应用 | 允许查文档，自己完成小功能关键逻辑、解释原理，并处理小变更或故障。 |
| 面试 | 用小实验支撑理解，独立解释原理、判断适用边界、说明选择依据并回答追问。 |
| 兼顾 | 选定本轮两方面必需成果与验收，不默认叠加全部内容。 |

进度区分未验证、提示下完成、独立完成与延迟后通过，并记录方向和条件。换方向保留有效证据，补查新目标的差距。继续时先读记录，用一个相关旧知识小挑战检查保持，针对薄弱点补练。

## 资料与适用边界

AI 组织主线，一手资料核对关键语义、版本与保证，实验验证明确场景，教材补充理解缺口。正常示例跑通不证明未覆盖的故障或并发边界，读笔记本身也不证明掌握。

具体流程与模板由 skill 包内参考文件维护；本文记录整体设计。方法证据与设计推导分开，实际教学效果仍需真实使用验证。

## 本次验证

2026-10-30，对正式更新稿进行了以下检查：

- skill-creator 官方格式校验、界面元数据解析，以及本地引用和独立打包检查。
- 一次独立场景试跑：已有应用计划改为面试方向，原 20 分钟预算只剩 5 分钟，旧笔记包含读取会延长固定 TTL 的误解。
- 试跑实际更新了计划、笔记和进度，缩小范围并修正解释，保留尚未验证的能力状态，停在等待学习者预测的位置；未代跑后宣布掌握。

试跑使用临时目录和本地练习模块，未改动真实学习项目。这是一个行为场景与结构校验，不代表长期教学效果已验证。上述验证在首次上传 GitHub 前完成。
